# company-vetting

공고를 낸 회사가 지원할 만한 곳인지 공개 출처로 확인하고 등급을 매긴다. 공고가 프로필에 맞는지는 판정하지 않는다. 그 판정은 discovery-reviewer가 한다.

출처별 요청 방법과 응답 필드는 `references/sources.md`에 있다. 검증을 시작하기 전에 읽는다.

## 1. 입력

오케스트레이터 프롬프트에 배치 ID와 회사 목록, 프로필 경로(`_discover/01_profile.json`), 출력 경로가 있다. 프로필은 `role_family`(직무군 키)를 읽어 5절의 지원 직무 조직 근거를 고를 때만 쓴다. 회사마다 아래 값이 온다.

```json
{
	"company": "씨메스로보틱스",
	"score": 3,
	"postings": [{ "title": "Frontend 개발자", "url": "https://www.wanted.co.kr/wd/390372", "source": "wanted" }]
}
```

회사 항목에 `company_id`(플랫폼 회사 ID)와 `business_number`(사업자등록번호, 점핏과 리멤버 공고에만 있다)가 올 수 있다. `_discover/03_candidates.json`에서 같은 회사의 공고를 찾으면 수집 단계가 뽑은 `skills`, `location`도 있다. 요청 없이 쓸 수 있으니 먼저 읽는다. `business_number`가 있으면 앞 6자리로 국민연금 행을 고른다. 국민연금 파일의 사업자등록번호가 앞 6자리뿐이라 이름이 같은 회사를 가리는 데 쓴다.

1차 검증은 `_cache/nps/`의 국민연금 가입 사업장 파일 두 개(최신 달과 12개월 전 달)를 쓴다. 오케스트레이터가 회사 검증을 띄우기 전에 받아 둔다(`references/sources.md` 국민연금 절). 파일이 없으면 company-vetter는 받지 않고 1차의 국민연금 조회를 사람인 기업정보로 대신한다.

## 2. 같은 회사인지 확인

이름이 같은 다른 회사의 값을 섞으면 직원 수와 투자, 레드 플래그가 모두 다른 회사 것이 된다. 2026-10-12 표본에서 "페어리"는 원티드와 THE VC, 사람인을 합쳐 대표자가 다른 회사 일곱 곳 이상으로 나왔고, 국민연금 파일(2026-08)에는 이름에 "페어리"가 들어간 사업장이 다섯 곳 있었지만 표본 회사는 없었다. "코딧"은 THE VC 검색에서 영문명이 같은 신용보증기금(KODIT)과 함께 나왔고, GitHub의 `Codit` 조직은 홈페이지가 codit.eu인 다른 회사였다.

1. 공고에서 기준 회사를 정한다. 원티드 공고 URL이면 `/api/v4/jobs/{id}`의 `.job.company.id`, 회사 항목에 `company_id`나 `business_number`가 있으면 그 값이 기준이다. 나인하이어나 그리팅 공고면 서브도메인을 영문명 후보로 쓴다. 표본 페어리는 `pairy.ninehire.site`의 pairy가 THE VC slug와 같았다.
2. 출처에서 확인 항목을 모은다: 홈페이지 도메인, 대표자, 설립연도, 도로명 주소의 시군구와 도로명, 업종, 대표 제품명.
3. 다른 출처의 결과는 확인 항목 중 두 개 이상이 맞을 때만 같은 회사로 쓴다. 국민연금은 도로명 주소와 업종, 블라인드는 `sameAs` 도메인, 사람인은 대표자명과 설립일, THE VC는 제품명과 대표자로 맞춘다.
   - 국민연금에서 같은 이름의 행이 여럿인데 공고 근무지 시군구와 맞는 행이 없으면, 사람인 회사 검색 1회로 본사 주소를 얻어 고른다. 공고 근무지가 본사가 아닌 경우가 있다(아이벡스는 공고가 서초구, 본사는 용인 수지구였다).
   - 도로명이 출처마다 달라도(이전, 표기 차이) 사람인 `EmployeeChart` 최근 값과 국민연금 가입자 수가 같으면 같은 회사로 본다.
   - 블라인드 `sameAs` 도메인이 홈페이지와 다르면 홈페이지 주소로 요청을 보내 리다이렉트되는 도메인과 비교한다. 같은 곳으로 가면 같은 회사다(inexcoin.com과 inexkr.com, aiv.ai와 aivexvision.ai).
4. 사명이 바뀐 회사는 새 이름으로 찾고 옛 이름을 `aliases`에 넣는다. 씨메스는 2026-03에 씨메스로보틱스가 됐다. 국민연금 파일에는 2025-08에 "주식회사 씨메스", 2026-08에 "씨메스로보틱스 주식회사"로 같은 사업자등록번호(앞 6자리 220888)와 주소로 있었고, 블라인드에는 "씨메스"로 남아 있다.
5. 이름 검색 후보가 둘 이상인데 확인 항목으로 가르지 못하면 더 찾지 않고 `grade`를 `unknown`으로 둔다. `summary`에 "동명 회사 N곳, 확정 못 함"을 쓰고 `evidence`에 후보 페이지 URL을 넣는다.

## 3. 두 단계로 검증

한 번 실행에 검증 후보가 200곳에서 500곳 나온다. 모든 회사를 끝까지 보지 않고, 1차에서 직원 수와 강한 레드 플래그만 보고 걸러진 회사는 거기서 끝낸다. 1차를 통과한 회사만 2차에서 등급을 매긴다.

### 1차: 직원 수와 강한 레드 플래그

배치 전체를 1차로 먼저 돌리고 2차로 넘어간다. 회사당 요청은 **2회까지**다. 국민연금 파일 조회는 로컬 파일 읽기라 세지 않는다.

1. **국민연금 조회(요청 0회)**: 배치의 회사 이름 전부를 `references/sources.md` 국민연금 절의 스크립트에 한 번에 넣는다. 최신 가입자 수와 12개월 전 가입자 수, 1년 증감, 업종, 도로명 주소, 가입 상태가 나온다. 같은 이름 행이 둘 이상이면 공고 `location`의 시군구로 고른다.
2. **묶음 뉴스 검색(회사당 약 0.1회)**: 회사 이름 10개를 OR로 묶어 구글 뉴스 RSS로 최근 1년 회생, 파산, 폐업, 체불, 정산, 구조조정 기사를 찾는다. 결과가 100건에서 잘리면 다섯 곳씩 나눠 다시 보낸다. 제목에 회사 이름과 레드 플래그 단어가 함께 있는 기사만 그 회사의 후보로 둔다. 후보 기사가 같은 회사 이야기인지 제목만으로 모르겠으면 그 회사 이름에 업종이나 제품명을 붙여 단독 검색을 1회 보낸다.
3. **국민연금에서 못 찾은 회사(요청 2회까지)**: 사람인 회사 검색 1회로 정식 법인명, 대표자, 주소를 얻어 국민연금 결과를 다시 찾는다. 그래도 없으면 THE VC WebSearch 1회로 폐업 여부와 임직원 수를 본다. 국민연금 가입 상태가 2(탈퇴)인 회사도 THE VC로 폐업 여부를 본다.

1차 판정은 아래 순서로 한다.

| 조건                                                                                      | 결과                                                       |
| ----------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 회생, 파산, 폐업, 임금 체불, 정산 지연, 구조조정 중 하나가 확인됐다(5절 강한 레드 플래그) | `X`로 끝낸다                                               |
| 국민연금 업종이 "임시 및 일용 인력 공급업"이나 "상용 인력 공급 및 인사관리 서비스업"이다  | `X`(파견이나 SI 주력)로 끝낸다                             |
| 국민연금과 사람인, THE VC 어디에도 직원 수가 없다                                         | `unknown`으로 끝낸다. `summary`는 "직원 수 근거 없음"      |
| 국민연금 탈퇴 상태이고 THE VC에 폐업 기록이 없다                                          | `unknown`으로 끝낸다. `summary`는 "국민연금 탈퇴(YYYY-MM)" |
| 그 밖                                                                                     | 2차로 넘긴다. 1차에서 얻은 값은 그대로 쓴다                |

1차에서 끝난 회사는 확인하지 못한 필드를 null로 두고 출력에 넣는다.

### 2차: 투자, 매출, 평점, 지원 직무 조직

1차를 통과한 회사만 본다. 회사당 요청은 **10회까지**다. 1차에서 이미 보낸 요청은 다시 보내지 않는다.

| 순서 | 출처                    | 요청 | 얻는 것                                                    | 건너뛰는 경우                                              |
| ---- | ----------------------- | ---- | ---------------------------------------------------------- | ---------------------------------------------------------- |
| 1    | 사람인 회사 검색        | 0~1  | 대표자, 설립일, 주소, 최근 연도 매출과 영업이익, 상장 표시 | 1차에서 이미 했으면                                        |
| 2    | 원티드                  | 0~2  | 기준 회사, 홈페이지, 태그, 매출(KODATA)                    | 공고가 원티드가 아니고 사람인으로 회사가 확정됐으면        |
| 3    | THE VC                  | 1~2  | 최근 투자 라운드와 날짜, 상장, 폐업                        | 사람인에 코스피나 코스닥 상장 표시가 있으면 생략할 수 있다 |
| 4    | 구글 뉴스 RSS 투자 기사 | 0~1  | 투자 유치 금액과 날짜                                      | 3에서 시리즈 B 이상이 확인되면                             |
| 5    | 블라인드                | 1~2  | 평점, 리뷰 수, 회사 도메인                                 | 없음. 이름을 바꿔 한 번 더 넣을 수 있다                    |
| 6    | 지원 직무 조직 근거     | 0~2  | 5절의 직무별 근거                                          | `03_candidates.json`의 공고 값으로 충분하면 0회            |
| 7    | DART                    | 0~2  | 상장 시장, 최근 1년 공시 제목                              | 사람인 정보에 상장도 외부감사법인도 없으면                 |

- THE VC는 WebSearch(`allowed_domains: ["thevc.kr"]`) 요약으로만 읽는다. 회사 페이지를 curl이나 WebFetch로 받지 않는다. 페이지에 "무단 사용, DB화 금지" 문구가 있어 사용자가 2026-10-12에 검색 요약만 쓰기로 정했다. 요약에 라운드나 날짜가 빠지면 뉴스 검색과 DART로 채우고, 그래도 없으면 null로 둔다.
- 6은 직무별로 WebSearch 한 번으로 본다. 개발 직군은 `"{회사명} 기술 블로그"`, 디자인 직군은 `"{회사명} 디자인 블로그"`, 그 밖 직군은 `"{회사명} {직무 이름}"`으로 찾는다. 개발 직군의 GitHub는 A 등급 후보인데 다른 근거가 없을 때만 본다(인증 없는 API는 시간당 60회).
- 같은 출처에서 두 번 실패하면 그 출처를 건너뛰고 `evidence`에 "실패: {URL} {상태 코드}"를 남긴다.

## 4. 값 채우기

모르는 값은 null로 둔다. 다른 값에서 계산할 수 있어도 출처에 없는 숫자는 만들지 않는다.

| 필드                      | 규칙                                                                                                                                                                                                                                                                    |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `company`                 | 입력의 `company`를 한 글자도 바꾸지 않는다. 리포트 단계가 이 값으로 공고와 맞춘다                                                                                                                                                                                       |
| `aliases`                 | 출처에서 본 같은 회사의 다른 표기. 법인 표기("씨메스로보틱스 주식회사"), 영문명, 블라인드나 THE VC 이름, 사명 변경 전 이름                                                                                                                                              |
| `headcount`               | 국민연금 파일 최신 달의 가입자 수. 없으면 사람인 `EmployeeChart.total`의 마지막 값, 원티드 `companySummary.employee.total`(`source`가 NPS일 때), THE VC 최신 임직원 수 순으로 쓴다                                                                                      |
| `headcount_change_1y`     | 국민연금 파일 두 개의 (최신 값 - 12개월 전 값) / 12개월 전 값, 소수 둘째 자리 반올림. 국민연금으로 못 구하면 사람인 `EmployeeChart.total`의 마지막 값과 12개 앞 값으로 같은 계산을 한다. 둘 다 없으면 null                                                              |
| `funding.stage`           | "시드", "프리A", "시리즈A", "시리즈B", "시리즈C", "시리즈D 이상", "M&A", "라운드 미상" 중 하나. THE VC `lastRound`를 옮기고, 라운드 이름 없이 투자 기사만 있으면 "라운드 미상". 정부 지원금과 구주 인수는 라운드로 치지 않는다                                          |
| `funding.total_krw`       | 출처가 누적 투자액을 숫자로 적었을 때만. 원티드 "누적투자100억이상" 태그와 THE VC 라운드 금액(로그인 없이 보면 가짜 값)은 쓰지 않는다                                                                                                                                   |
| `funding.last_amount_krw` | 마지막 투자 한 번의 금액. 투자 기사나 공시가 금액을 적었을 때만 쓴다. 라운드 이름이 없어도("라운드 미상") 채운다. 단계 판정에서 100억 원 이상이면 성장 스타트업으로 본다                                                                                                |
| `funding.last_date`       | 마지막 투자 유치의 `YYYY-MM`. THE VC 검색 요약이나 투자 기사의 날짜                                                                                                                                                                                                     |
| `listed`                  | 사람인에 코스피, 코스닥, 코넥스 표시가 있거나 DART 시장 구분이 `kospi`, `kosdaq`, `konex`이면 true. DART 시장 구분이 `etc`(기타법인)이거나 THE VC 검색 요약, 사람인이 비상장으로 적었으면 false. 어디에도 없으면 null                                                   |
| `revenue`                 | 사람인 검색 결과나 재무 탭의 최근 연도 `year`, 매출 `krw`, 영업이익 `operating_profit_krw`. 사람인에 없으면 원티드 `companySummary.sales.total`과 그 `updatedAt`의 연도, 영업이익 null. 둘 다 없으면 `revenue`를 null                                                   |
| `rating`                  | 블라인드 `{ "site": "블라인드", "score": 4.0, "reviews": 100 }`. 블라인드에 없으면 null                                                                                                                                                                                 |
| `tech_signals`            | 지원 직무 조직 근거. "종류 URL" 형식 문자열이고 종류는 5절의 직무별 근거 이름이다. 공고 기술 스택은 "공고 기술 스택 C++, Python, OpenGL https://..."처럼 기술 이름을, 공고 팀과 업무는 "공고 팀과 업무 그로스팀, CRM 캠페인 운영 https://..."처럼 적힌 내용을 함께 쓴다 |
| `red_flags`               | `{ "type", "date", "source" }`. `type`은 5절 표의 이름, `date`는 사건이나 보도의 `YYYY-MM`, `source`는 기사나 공시, 회사 페이지 URL                                                                                                                                     |
| `evidence`                | 값을 읽은 페이지 URL 전부와 실패 기록. 국민연금 값을 썼으면 `https://www.data.go.kr/data/15083277/fileData.do`를 넣는다                                                                                                                                                 |
| `checked_at`              | 그 회사를 검증한 날짜. 캐시가 30일 동안 이 결과를 다시 쓴다                                                                                                                                                                                                             |
| `summary`                 | 40자 이내. 리포트 "회사 근거" 칸에 그대로 들어간다. 자금 근거, 직원 수와 증감, 평점이나 레드 플래그 순으로 쓴다. 예: "시리즈C 500억(2024-12), 직원 200명(+6%)", "2025-10 폐업, 공고만 남음"                                                                             |

금액 표기 "112억 578만원"은 11,205,780,000원, "- 174억 5,099만원"은 -17,450,990,000원, 사람인 검색 결과의 "112억"은 11,200,000,000원으로 바꾼다.

## 5. 등급

위에서부터 처음 맞는 등급을 준다. 1차에서 끝난 회사는 3절 1차 판정을 따른다.

| 등급      | 뜻          | 조건                                                                                                                     |
| --------- | ----------- | ------------------------------------------------------------------------------------------------------------------------ |
| `unknown` | 판단 불가   | 2절에서 회사를 하나로 확정하지 못했다                                                                                    |
| `X`       | 제외        | 강한 레드 플래그가 하나 이상 있다                                                                                        |
| `C`       | 주의        | 약한 레드 플래그가 하나 이상 있다                                                                                        |
| `unknown` | 판단 불가   | 직원 수, 자금이나 매출, 평점 세 가지 중 두 가지 이상을 찾지 못했다                                                       |
| `A`       | 추천할 만함 | 자금이나 수익 근거가 하나 이상 있고, 직원 수가 늘거나 유지되고, 레드 플래그가 없고, 지원 직무 조직 근거가 하나 이상 있다 |
| `B`       | 무난함      | 레드 플래그는 없고 A의 조건 중 일부만 맞는다                                                                             |

A의 조건은 아래로 판단한다.

- 자금이나 수익 근거: 시리즈 B 이상 투자, 최근 2년 안에 한 번에 100억 원 이상 투자를 유치한 기사, 최근 회계연도 영업이익 흑자, 코스피나 코스닥 상장 중 하나.
- 직원 수 유지나 증가: `headcount_change_1y`가 -0.05 이상. null이면 이 조건을 채우지 못한 것으로 본다.
- 지원 직무 조직 근거: 프로필 `role_family`로 아래에서 고른다. `role_family`가 없으면 프로필 `role`로 고른다. 찾은 근거는 아래 이름을 종류로 `tech_signals`에 담는다.
  - 개발 직군(`frontend`, `backend`, `fullstack`, `android`, `ios`, `crossplatform`, `data_engineer`, `ml`, `devops`, `qa`, `security`, `game_dev`): 회사 도메인이나 회사 이름의 "기술 블로그", 회사 홈페이지와 `blog` 도메인이 같은 "GitHub 조직", 최근 2년 안의 "컨퍼런스 발표", 기술 이름이 세 개 이상 적힌 공고("공고 기술 스택") 중 하나.
  - 디자인 직군(`product_designer`, `visual_designer`): 회사 도메인이나 회사 이름의 "디자인 블로그", 공개된 "디자인 시스템", 회사 디자인 팀의 "포트폴리오 사이트"(Behance, Dribbble 같은 곳의 회사 계정 포함), 디자인 팀 구성이나 협업 방식과 구체적 업무가 함께 적힌 지원 직무 공고("공고 팀과 업무") 중 하나. 블로그나 포트폴리오를 따로 운영하는 회사가 드물어서 공고 본문도 근거로 인정한다.
  - 그 밖 직군: 팀 구성과 구체적 업무가 함께 적힌 지원 직무 공고("공고 팀과 업무"), 최근 2년 안에 회사 사람이 그 직무로 한 외부 "직무 발표", 회사 이름으로 낸 그 직무의 "직무 아티클" 중 하나.

레드 플래그는 회사를 확정한 뒤의 근거만 쓴다. 기사는 제목이나 본문에 그 회사 이름과 2절의 확인 항목 하나 이상(대표자, 제품명, 업종, 도메인)이 함께 있어야 한다.

| 세기 | `type`           | 조건                                                                                                                                                                                                                                  |
| ---- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 강   | 회생             | 최근 1년 안에 회생 절차 신청이나 개시 보도, 공시                                                                                                                                                                                      |
| 강   | 파산             | 최근 1년 안에 파산 신청이나 선고 보도                                                                                                                                                                                                 |
| 강   | 폐업             | 법인이 폐업했거나 휴업 중이다. 시기와 상관없다. THE VC `status` "폐업"이나 `history`의 폐업 기록, 폐업 보도                                                                                                                           |
| 강   | 임금 체불        | 최근 1년 안의 임금이나 퇴직금 체불 보도                                                                                                                                                                                               |
| 강   | 정산 지연        | 최근 1년 안에 판매자나 거래처 대금 정산이 밀렸다는 보도                                                                                                                                                                               |
| 강   | 구조조정         | 최근 1년 안에 전사 희망퇴직, 권고사직, 인력 감축 보도. 한 부서 개편이나 조직 개편 기사는 해당하지 않는다                                                                                                                              |
| 강   | 파견이나 SI 주력 | 국민연금이나 사람인, 원티드 업종이 인력 공급업(1차 판정 표의 두 업종)이거나, 회사 소개와 공고가 고객사 상주, 파견, SI, SM을 주 업무로 적었다                                                                                          |
| 약   | 직원 감소        | `headcount_change_1y`가 -0.20 이하                                                                                                                                                                                                    |
| 약   | 낮은 평점        | 블라인드 평점 2.5 이하이면서 리뷰 30건 이상                                                                                                                                                                                           |
| 약   | 장기 상시 공고   | 같은 공고가 1년 넘게 열려 있다는 날짜 근거가 있다. 직전 발굴 실행(`_discover_*/02_postings_*.json`)이나 날짜가 적힌 검색 결과에 같은 URL이 1년 이상 전 기록으로 있을 때만 쓴다. 원티드 공고 ID가 오래돼 보이는 것만으로는 쓰지 않는다 |

적자는 레드 플래그가 아니다. 영업손실이 크면 `summary`에 적는다. 판단은 리포트를 읽는 사람이 한다.

## 6. 출력 스키마

`_discover/04_vetting_{batch}.json`에 쓴다. 맡은 회사가 전부 실패해도 파일은 쓴다.

```json
{
	"batch": "vet-1",
	"checked_at": "2026-10-12",
	"companies": [
		{
			"company": "클로버추얼패션",
			"aliases": ["CLO Virtual Fashion"],
			"grade": "A",
			"summary": "시리즈C, 직원 320명(+18%), 평점 3.9",
			"headcount": 320,
			"headcount_change_1y": 0.18,
			"funding": {
				"stage": "시리즈C",
				"total_krw": 60000000000,
				"last_amount_krw": 50000000000,
				"last_date": "2024-12"
			},
			"listed": false,
			"revenue": { "year": 2025, "krw": 50000000000, "operating_profit_krw": 3000000000 },
			"rating": { "site": "잡플래닛", "score": 3.9, "reviews": 210 },
			"tech_signals": ["기술 블로그 https://..."],
			"red_flags": [{ "type": "임금 체불", "date": "2026-03", "source": "https://..." }],
			"evidence": ["https://...", "https://..."],
			"checked_at": "2026-10-12"
		}
	]
}
```

- 위 값은 형식 예시다. 실제 값은 4절 규칙으로 채운다.
- 모르는 값은 null. 추측하지 않는다.
- `summary`는 40자 이내, 리포트의 "회사 근거" 칸에 그대로 들어간다.
- `grade`는 A, B, C, X, unknown 중 하나.
- `funding`은 값을 하나도 못 찾아도 세 필드가 null인 객체로 둔다. `revenue`와 `rating`은 못 찾으면 null이다.
- 맨 위 `checked_at`은 배치를 끝낸 날짜, 회사마다의 `checked_at`은 그 회사를 검증한 날짜다.
- 입력에 있던 회사는 전부 `companies`에 넣는다. 1차에서 끝난 회사와 요청이 실패해 아무것도 못 얻은 회사도 넣는다.

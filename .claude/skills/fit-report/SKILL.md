# fit-report

리포트를 읽는 사람은 어느 공고에 지원할지 정하려는 사람이다. 그 판단에 쓰이지 않는 정보는 리포트에 넣지 않는다.

## 1. 합치기

`_workspace/02_postings_*.json`을 전부 읽는다.

**파일끼리 겹칠 때**

- 같은 공고(같은 URL)가 여러 파일에 있으면 수정 시각이 늦은 파일의 값을 쓴다. Chrome 재수집(`browser-2` 등)이 목록 값만 있던 공고를 채운 경우다.
- `rerun-*` 파일은 그 파일에 든 기업의 이전 공고를 전부 대체한다. 부분 재실행 결과가 이전 결과를 대체한다.
- 그 밖에는 대체하지 않는다. 같은 기업이라도 자사 페이지와 플랫폼에서 각각 모은 공고는 모두 남기고 아래 같은 공고 판별로 합친다. 플랫폼 파일이 늦게 쓰였다고 자사 공고를 버리면 자사 링크와 상세 값이 사라진다.

**같은 공고 판별**: 기업이 같고, 제목에서 괄호와 대소문자, 공백, "경력", "채용", "모집"을 지운 문자열이 같으면 같은 공고다. 제목이 조금 달라도 상세 URL이 같으면 같은 공고다.

**링크 고르기**: 같은 공고가 여러 출처에 있으면 아래 순서로 첫 번째 링크를 쓴다. 플랫폼 공고에 `original_url`이 있으면 그것을 자사 링크로 본다.

1. 자사 채용 페이지 (`source: career`)
2. 원티드, 리멤버, 잡플래닛, 사람인, 직행, 점핏, 잡코리아, 캐치 순
3. 링크드인

필드 값이 출처마다 다르면 자사 페이지 값을 쓴다.

## 2. 거르기

걸러지지 않은 공고가 섞이면 사용자가 리포트를 받을 때마다 다시 골라내야 한다. 애매하면 빼고 `_workspace/04_dropped.md`에 이유를 남긴다. 사용자는 제외 기록을 보고 되살릴 수 있다.

**기업**

- 프로필 `exclude_companies`에 있는 기업
- `data/companies.md`의 "제외한 기업" 절에 있는 기업. 플랫폼에는 운영사 이름(예: 브랜디의 뉴넥스)으로 올라올 수 있으니 이유 열에 적힌 이름도 맞춰 본다.
- 레지스트리 밖 기업은 대기업 계열사나 기업가치 1조 원 이상 유니콘으로 확인될 때만 남긴다. 상장사라는 이유만으로는 남기지 않는다. 코스닥 소형 상장사가 섞여 리포트가 흐려진다. 확인은 이미 아는 사실로 하고, 모르면 WebSearch 한 번으로 본다. 그 검색에서 최근 1년 안의 회생, 파산, 임금 체불, 정산 지연 보도가 나오면 뺀다. 확인이 안 되면 뺀다.

**공고**

- 헤드헌팅이나 서치펌이 올린 공고, 회사명을 가린 공고("비공개", "국내 대기업", "유망 스타트업" 같은 표기)
- 파견, 도급, 고객사 상주 근무(SI 상주 포함)
- `employment`가 계약직, 인턴, 아르바이트, 프리랜서인 공고. 프로필 `notes`에 허용한다고 적혀 있으면 남긴다.
- 마감일이 오늘보다 앞선 공고
- 프로필 `locations`가 비어 있지 않은데 근무지가 거기 없고 원격 근무 표시도 없는 공고
- 아래 3의 판정이 제외인 공고

## 3. 판정

`y`는 프로필의 `years`다.

**연차**

| 공고 요건                                                | 판정                                                                                                                                    |
| -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `min_years ≤ y`이고 `max_years`가 없거나 `max_years ≥ y` | 맞음                                                                                                                                    |
| `y < min_years ≤ y + 2`                                  | 경계 (요건보다 짧음)                                                                                                                    |
| `max_years < y ≤ max_years + 2`                          | 경계 (요건보다 김)                                                                                                                      |
| 그 밖                                                    | 제외                                                                                                                                    |
| `min_years`, `max_years` 모두 없음                       | 제목으로 본다. "신입", "주니어", "Junior"인데 `y ≥ 3`이면 제외. "리드", "Lead", "Head", "Principal"인데 `y < 7`이면 경계. 나머지는 맞음 |

**직무**: 제목이나 주요 업무가 `role`이면 일치, `adjacent_roles`면 인접, 둘 다 아니면 제외.

**기술**: 공고의 `skills`와 프로필 `skills_core`가 겹치는 수를 센다. 공고에 기술이 하나도 적혀 있지 않으면 기술 조건은 보지 않는다.

| 등급 | 조건                                                                                      |
| ---- | ----------------------------------------------------------------------------------------- |
| 추천 | 직무 일치, 연차 맞음, 기술이 2개 이상 겹치거나 공고에 기술이 없음                         |
| 검토 | 추천은 아니지만 제외 조건에 걸리지 않음. 예: 직무 인접, 연차 경계, 기술이 1개 이하로 겹침 |
| 제외 | 직무 제외 또는 연차 제외                                                                  |

프로필 `notes`의 희망 조건(예: "SI 성격 포지션 제외")에 걸리면 등급을 한 단계 내리고 이유를 적는다.

## 4. 신규 표시

직전 리포트가 주어지면 그 파일의 링크 목록을 읽는다. 이번 공고의 링크가 거기 없고 같은 기업과 같은 제목도 없으면 포지션 앞에 `신규`를 붙인다. 직전 리포트가 없으면 아무것도 붙이지 않는다.

## 5. 정렬

`data/companies.md`의 `티어` 열 순서(S, A+, A, B+, B, 빈칸)로 놓고, 같은 티어 안에서는 레지스트리 행 순서를 따른다. 레지스트리 밖 기업은 맨 뒤에 둔다. 티어는 공고의 `company`와 같은 이름의 행에서 찾는다. 수집 단계에서 계열사가 레지스트리에 있으면 `company`를 그 행 이름으로 적어 두므로, 그룹 사이트 공고도 계열사 티어를 따른다.

## 6. 리포트 형식

아래 형식을 그대로 쓴다. 비어 있는 절은 제목째 뺀다.

```markdown
# 채용공고 {YYYY-MM-DD}

{role} 경력 {years}년 기준. 기업 {확인한 기업 수}곳 확인, 공고 {추천+검토}건 (신규 {n}건)

## 추천

| 티어 | 기업 | 포지션                             | 경력     | 마감 | 맞는 이유          | 링크                |
| ---- | ---- | ---------------------------------- | -------- | ---- | ------------------ | ------------------- |
| S    | 토스 | 신규 Frontend Developer (Payments) | 3년 이상 | 상시 | React, 결제 도메인 | [자사](https://...) |

## 검토

| 티어 | 기업 | 포지션 | 경력 | 마감 | 걸리는 점 | 링크 |
| ---- | ---- | ------ | ---- | ---- | --------- | ---- |

## 확인 못 한 곳

두나무 (페이지 오류), 잡플래닛 (Chrome 미연결)
```

- **티어**: 레지스트리 `티어` 값. 비어 있거나 레지스트리 밖 기업이면 "-".
- **기업**: `company`. `affiliate`가 있고 `company`와 다르면 "비바리퍼블리카 (토스증권)"처럼 괄호로 붙인다.
- **경력**: `experience_raw`를 짧게 줄인다. "경력 3년 이상" 대신 "3년 이상", 없으면 "미기재".
- **마감**: `YYYY-MM-DD`는 `MM-DD`로 줄인다. 상시와 미기재는 그대로.
- **맞는 이유**: 겹친 기술과 도메인을 20자 안쪽으로. 문장으로 쓰지 않는다.
- **걸리는 점**: 검토로 내린 이유 하나를 20자 안쪽으로. 예: "요건 7년 이상", "백엔드 비중 큼".
- **링크**: 링크 텍스트는 출처 이름이다. 자사 페이지는 "자사".
- **확인 못 한 곳**: 모든 수집 파일의 `unreachable`을 모으되, 나중 배치(`browser-2`, `rerun-*`)에서 읽어 낸 곳은 뺀다. 괄호 안 이유는 `js`면 "JS 렌더링", `login`이면 "로그인 필요", `chrome_unavailable`이면 "Chrome 미연결", 그 밖은 "페이지 오류"로 쓴다.
